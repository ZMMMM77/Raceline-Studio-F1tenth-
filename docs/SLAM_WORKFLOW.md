# 真实建图优化流程（1、2、3、5）

## 导入

- 有可靠 CSV 时：选择 CSV 导入，同时提供同一坐标系的 PNG/PGM 和 YAML。默认“有地图时以原始地图为准”。保留 CSV 路线形状，只按弧长重采样，不自动重新居中。CSV 自带宽度默认不构造障碍墙。
- 只有地图时：自动提取参考线。小孔填补面积默认 0.01 m²、补缝半径默认 0.05 m；可关闭或设为 0。操作仅发生在用于提取骨架的副本上。
- 原始图片、YAML、占据栅格和距离场不修改。未知区域仍不可通行。提取线若穿过原始障碍会拒绝导入；复杂岔路应使用有序 CSV。
- 如 CSV 宽度本身可靠，可以选择“保留 CSV 宽度，同时检查地图”。没有 YAML 的图片只作参考，不具备米制障碍约束。
- YAML 的 resolution、origin、旋转和阈值必须正确；此更新不自动标定地图与 CSV。

## 约束与优化

- 原始地图模式：射线宽度只限制控制点的横向搜索范围，不把端点连成墙。边界净空直接由原始地图距离场约束，避免弯道端点跳变产生虚构尖刺。
- 先寻找满足车辆净空、曲率、前进方向要求的路线并做加密检查，再优化曲率平方积分（或所选路程目标）。
- 各阶段共用求解时限；保留此前的停滞条件。后续求解失败时，可返回此前通过加密检查的可行路线，并明确标记提前结束而非正常收敛。
- 仍使用整车外接圆加额外余量；没有通过缩小实际车辆尺寸来消除报警。有限采样检查不构成全局最优或连续区间证明。
- 导出新增 reference_path.csv（两列 x/y，适合配合原图与 YAML 再导入）。centerline.csv 宽度在地图模式下属于射线诊断值；请勿脱离地图把它当作精确墙体。
- import_report.json 记录边界模式、相邻宽度跳变、参考线最小净空和地图副本清理统计。extraction_mask.png 可查看清理副本。

## Levine 数值运行记录

使用原始 levine_1st_map.pgm/yaml；默认清理填孔 0 像素、补缝封闭 7 个空闲像素，全部只作用于副本。

运行参数：后轴参考点、轴距 0.3302 m、转角 24°、车宽 0.31 m、车长 0.58 m、后悬 0.20 m、额外余量 0 m；140 控制点、输出间距 0.1 m、时限 30 s、停滞窗口 50、阈值 0.1%。

206 次迭代，29.20 s 正常收敛；4200 点加密检查通过。路线长 30.03 m；曲率平方积分 4.79555 m⁻¹；最大曲率 1.32208 m⁻¹，限制 1.34836 m⁻¹；最小保守地图净空 0.434849 m，车辆要求 0.410396 m。

此结果不适用于原先的 0.604 m 净空要求，也不建议仅为求解成功而更改实车尺寸。运行记录中的可行性迭代计数早于粗网格计数修正，未包含粗网格；总迭代数正确。

## 更新后启动

结束现有计算后，在 Studio 服务终端按 Control+C，重新运行“start.command”，刷新页面并重新导入文件。仅刷新页面不会更新正在运行的 Python 后端。

安装器会在 backups/before_slam_workflow_* 保存原文件，检查文件哈希后逐个替换。旧的输出结果保留。
